# DataLab 全学科数据查找与获取设计

产品设计与实现约束，更新于 2026 年 10 月 22 日。目标是让不知道数据来源的分析人员，从一个问题出发，找到可获取的实际数据，取得真实文件，并带着来源和原问题进入分析。聊天查找、获取、我的数据及分析交接已实现；本文中的完整关系模型、预览和后续来源仍是扩展设计，以代码及验收结果为准。

产品以全学科为范围，统一处理对象、变量、时空范围、观测粒度和数据形态。来源覆盖逐步扩展，界面如实显示已检索范围。现有 NCBI Datasets、GEO、SRA 作为专业适配器保留，不决定首页语言和默认搜索领域。

## 产品主流程

“描述问题 → 理解数据需求 → 跨来源查找 → 比较适用性 → 获取并准备 → 开始分析”。

复用现有首页与 ChatPage。首页接收问题并进入聊天；需求澄清、查找卡片、数据候选和分析在聊天中完成，详细获取进度和已保存文件集中在同一窗口右侧的“数据获取”面板。用户既可点击消息中的操作，也可通过同一输入框补充条件、选择数据、获取、重试和分析。查找与获取各自持久化并关联会话，后台任务独立于页面生命周期；产品不新增独立查找页面或获取任务导航。查找、解析文件、下载均不要求创建分析沙盒。输入框底部保留原有“连接器”入口，明确知道数据来源的用户可直接选择；手选来源是本轮检索的硬约束。

| 阶段 | 用户操作 | 系统交付 |
| --- | --- | --- |
| 描述问题 | 输入自然语言，也可粘贴 DOI、来源链接或数据集编号 | 保留原问题，识别目标和已知约束 |
| 理解需求 | 修改提取的条件；也可选择“先看看有哪些数据” | 对象、变量、区域、时间、粒度、数据形态，区分硬约束与偏好 |
| 查找 | 在聊天中查看渐进结果，继续补充条件 | 持久查找卡片、多源结果、已查范围、来源失败状态、可继续的检索 |
| 比较 | 看候选卡的推荐理由、缺口和小预览，选择数据或组合 | 带明确查找修订与候选标识的选择，以及适用性证据与真实获取条件 |
| 获取 | 点击“获取数据”，或在输入框提出获取要求 | 聊天中简短回执、右侧逐项进度和结果，自动保存到“我的数据” |
| 使用 | 查看准备结果，点击或输入“开始分析” | 将明确的数据版本与选择范围绑定到原分析需求 |

缺失条件不全部追问。每次最多询问一到两个会显著改变检索方向的问题；能查就先查，并显示采用的假设。不得静默限定物种、国家或年份，也不得把年度数据作为月度要求的替代而不说明。

“找数据”默认止于准备结果；用户明确要求“找到后分析”时，在授权范围和输入检查通过后可以继续。下载完成不改变正在运行的分析输入；用户可以用于下一轮或新分析。

## 聊天内交互与恢复

ChatPage 是完整操作入口。每次查找在会话中形成一张持久查找卡片，显示原问题、当前条件、已查范围、来源进度和当前修订的候选；获取记录及准备结果仍关联对应候选和修订。候选来源说明、文件选择和分页在消息卡片内展开，获取任务与保存文件不再堆叠于聊天正文。每张查找卡片只保留一个简短回执，显示进行中、已保存及未完成项；点击“查看进度 / 查看文件”打开右侧面板并定位对应任务。

左侧“我的数据”承担跨会话文件管理；右侧“数据获取”汇总当前会话全部查找产生的任务，按“进行中 / 需处理 / 已完成”分组，已完成默认收起。面板内提供取消、重试、预览、下载到本地和加入分析输入；顶部入口可随时重新打开。数据获取、文件预览及工具视图共用右侧区域，互相切换，预览可返回数据获取。

首次发起获取且右侧空闲时可自动打开面板；用户关闭后继续后台获取，进度或完成事件不会重开面板、滚动聊天、抢占预览或修改分析输入。只有显式操作定位任务。窄屏使用全屏抽屉，支持关闭、Escape 和键盘焦点返回；“加入分析输入”经当前会话确认接收后回到输入框。刷新恢复服务端任务；切换会话清空客户端上下文，分享页不读取或展示私有获取任务。

聊天输入在查找、获取或准备期间保持可用。用户可以补充“改成月度数据”“再找包含收入的来源”，也可以要求获取、取消、重试某项或开始分析。细化条件创建新的查找修订；旧查询、候选排序、已选数据和获取记录继续保留，新的修订不覆盖旧记录，也不自动取消或替换旧修订已经开始的获取。用户可明确继续旧修订或取消其获取。

所有卡片操作绑定服务端标识：查找使用 search_id 与 revision_id，候选选择同时携带 candidate_id，获取使用 manifest_id 与 job_id。用户从卡片操作时，输入框可显示可移除的“针对这次查找 / 这份数据 / 这次获取”上下文标签；这些标签承载不透明标识，用户无需手输 ID。自然语言命令和点击操作调用同一服务，并提交相同的目标标识。

同一会话有多个查找或多个修订时，不能按最新一张卡片猜测“第二个”“重新下载”的对象。只有指向明确卡片、修订及当时排序的引用才可解析为候选标识；仍有歧义时只要求用户点选目标或补明名称，不启动可能指向错误数据的操作。输入框条件改变后，旧卡片的按钮仍指向其原 search_id / revision_id / job_id，不能被全局“当前搜索”变量重定向。

服务端会话历史保存查找、修订、候选选择和获取记录的关联；进行中的状态通过带游标的任务事件更新，重新打开或刷新聊天时按记录恢复。页面关闭或切换会话不停止后台任务，不清除历史；旧页面的晚到响应不能写入当前聊天。聊天中断线应显示状态暂未确认，并恢复读取服务端记录，不把连接中断当作获取失败。

分析开始时固定 AnalysisBinding 中的资产版本和文件/子集快照。正在运行的分析继续使用自己的快照；新查找结果、下载完成或聊天中新选的文件只进入待用选择。运行期间输入的新分析要求与其明确数据版本保留为下一轮请求，待执行入口可用后按用户要求开始；用户明确创建新分析时再使用独立的分析运行。不能因为准备完成自动中止、重启或改写正在运行的任务，也不要求用户重复已经清楚表达的获取或分析指令。

## 结果应帮助用户判断什么

结果的基本单位是有版本和来源的数据集。研究、实验、样本、文件及 API 查询结果分别建模，通过关系分组。

每张结果卡优先回答三个问题：包含什么、为什么适合、如何取得。显示名称、发布者、覆盖范围、观测单位或分辨率、关键变量或内容类型、格式与已知大小，以及“满足的条件 / 冲突 / 待确认”。字段缺失写“待确认”，不由模型补齐事实。

推荐理由必须引用已取回的源字段或页面证据。数据 DOI 索引能证明记录存在，不能证明文件可直接下载；网页搜索摘要属于线索，不能据此宣称拥有某些字段。用可解释的要求匹配替代未经校准的百分比。

| 获取状态 | 主操作 | 进入下一阶段的条件 |
| --- | --- | --- |
| 已核实可直接获取 | 获取并准备 | 已读到实际文件内容或非空接口观测值，且通过当前获取条件核验 |
| 已保存实体文件 | 下载到本机、加入分析输入 | 已完成下载并保存到个人数据 |

默认结果必须同时通过主题相关性判断和实体数据可获取性核验。只有 DOI、介绍页、申请权限、空文件、明确的 README/说明文档或元数据附件都不计为检索结果；无可用数据时明确说明，不用线索补数。大小本身不排除结果，未知大小也不冒充空文件。可获取性核验包括权威文件解析、受控实际内容读取、响应长度和类型检查；接口必须包含实际非空观测值。核验成功不代表完整下载完成，也不能保证来源此后不变化，正式下载仍核对实际长度、来源提供的校验和及完整内容摘要。

来源数据本身的适用性限制保存在 `limitations`；DataLab 的核验范围、获取方式、暂时错误等技术说明保存在 `system_notes`。结果卡只给出简短的已核验文件数量，不再展示通用系统获取说明区块；界面保留来源说明、获取进度、操作失败与重试入口。历史记录中的旧系统上限和核验文字在统一公开投影中迁移，不再混作来源内容。

分页保留来源游标，过滤后可继续查找；限流或超时显示“尚未完成核验”，不能冒充确定无结果。历史未核验候选不再展示，已经保存的文件及其任务继续可用。获取按钮再次核验来源；不向浏览器暴露内部下载地址。

聊天内的查找卡片保留服务端的相关性顺序，先显示前五条；“显示更多结果”先展开已经取得的结果，全部展开后才提供“继续查找”。来源名称可查看，但不按来源轮流交错结果。精确 DOI 或来源规范编号用于去重；不同版本保留，标题近似只能提示相关。已取回数量与来源报告的总数分开显示，不能把各来源总数相加当作去重后的数据集总量。分页或新结果到达不改变已有选择绑定的候选标识；用于自然语言引用的排序必须来自明确修订的结果快照。

多数据集场景可以推荐组合，例如教育投入表与就业表；必须核对连接键、覆盖交集、单位、粒度和变量定义。缺少这些信息时标为“待核验组合”，不自动拼接或宣称可以回答因果问题。

无命中与检索失败分开。查找卡片说明哪些来源完成、哪些暂不可用，以及具体可放宽的条件；保留已成功结果。扩展搜索范围需要更新可见条件，用户硬约束不被模型自行放宽。

## 当前检索相关性流程

检索按“原始意图路由 → 来源召回 → 语义证据判断 → 文件可获取性核验 → 稳定排序”执行。原问题始终保留；翻译后的关键词用于召回，不能代替原问题成为适用性判断标准。

1. **按完整需求选择来源。** 规划同时考虑研究对象、研究目的和明确限制，保存各来源的实际查询。共享地名或人群词不能把语言研究改成地理、遗传或其他研究。自动模式选择相关来源；手选模式保留用户范围，对缺少必要参数、无法形成忠实查询的来源说明原因，不制造占位参数、默认地点或日期。规划失败时使用原描述保守查询少量通用仓库；不自动遍历所有专业观测接口。规划与相关性判断沿用所属会话的模型配置并记录用量。
2. **明确普通多词的查询语义。** CKAN、Zenodo、BioStudies、RODARE 的普通主题词转换为显式 `AND`，复用 Dataverse 的共享处理逻辑；引号短语保持完整，用户明确指定的字段、布尔和其他高级表达式保留。各站默认检索语义不同，不能认为空格天然代表全部匹配。该处理减少只命中通用词的噪声，不能代替语义判断，也不对特定语言、国家或学科硬编码。
3. **先判断元数据是否支持原需求。** 服务按有界批次评估候选的研究对象、目的和硬约束，输出 `related / unrelated / uncertain`。肯定或否定判断必须带候选自身标题、描述或覆盖字段中的原文证据，服务验证引用确实存在，并检查判断维度与状态一致；伪造引用、缺失判断或模型失败均保留为待确认。仅共享词语、来源所在国家、文件可下载或来源排名均不是相关证据。独立完整标题或强标识的精确查找可使用确定性匹配；普通宽泛词不能据此绕过判断。
4. **相关候选再核验实际文件。** 新候选只有 `related` 才进入实际文件探测；`unrelated` 排除，`uncertain` 保留待重试而不展示为可获取结果。最终公开结果同时要求当前相关性证明、文件核验标记及匹配的文件选项证明。两个步骤分别回答“元数据支持相关吗”和“当前能取得实体内容吗”。
5. **服务端排序，前端保序。** 内部 `score` 是离散等级：直接支持对象及用途、已请求约束得到支持的候选优先；只支持同一研究的部分变量或覆盖条件待确认的候选次之。`rank` 根据对象、用途和约束的匹配维度进一步区分；同级使用标题及候选标识作确定性排序，避免网络返回速度决定顺序。新增更相关候选可以排在前面，原选择仍绑定候选标识。分值不作为百分比、准确率或满足全部分析要求的承诺对外显示；卡片只展示简短“匹配依据”。

相关性证明绑定规则版本、原始需求摘要和完整语义元数据摘要；元数据或规则变化后不能复用旧判断。读取已完成的历史查找时，如发现缺失或失效的证明，由持久 worker 重新评估，HTTP 轮询不直接重复调用模型。尚未通过的候选暂不展示，原获取任务和已保存文件继续保留。旧规划版本继续检索时重新规划并清理旧查询的分页游标，避免混用不同查询的分页。文件可获取性证明仍单独使用租约代次及证明标识，相关性判断不能替代其并发与归属校验。

待确认数量通过 `relevance_pending_count` 显示。运行中说明正在确认相关性，暂时结束时保留“继续查找”重试入口；模型超时、无效输出和证据不足不能显示为确定无结果。已经通过的判断可复用，待确认项继续评估；部分成功不因其他候选失败而丢失。前端保留旧版缺少展示字段的兼容处理，但服务端统一公开投影仍执行当前两项核验，不允许旧版“可下载”标签绕过判断。

**匹配依据仅反映元数据证据。** 它不能证明完整文件包含所有变量、记录可成功关联、样本质量合格、统计方法有效或最终分析可完成。多变量研究的一份组成数据可以作为相关候选，但缺失覆盖与关联条件必须写明，获取后的读取、预览和分析输入检查仍需独立完成。

## 全学科来源策略

使用受控来源目录描述主题覆盖、语言、数据形态、地区、检索能力、详情解析、文件枚举、官方子集、认证及限制。系统按需求选择少量相关来源并行搜索，先返回可用结果，再扩展；避免每个问题遍历全部来源。来源目录可以增加适配器，但不建设全站爬虫、知识库索引或科学站点发布平台。

| 层次 | 作用 | 首期设计 |
| --- | --- | --- |
| 跨学科数据索引 | 扩大数据集发现范围 | DataCite 数据 DOI 检索，后续解析其实际托管来源 |
| 跨学科数据仓库 | 从记录走到具体文件 | Zenodo 记录、版本、文件清单与获取 |
| 结构化领域接口 | 保留专业筛选与官方子集 | 新增 World Bank 指标接口；接入已有 NCBI 三类来源 |
| 网页线索 | 找到未直接接入的官方数据页 | 复用现有 SearchEngine，新增数据页识别与受控解析 |

DataCite 的公开 API 提供可发现 DOI 的元数据查询；本设计据此将其用于发现，而不将 DOI 直接当下载地址。[官方文档](https://support.datacite.org/docs/rest-api)

Zenodo API 提供已发布记录检索及文件访问，适合作为跨学科仓库适配器。[官方文档](https://developers.zenodo.org/)

World Bank API 支持按国家、指标和日期范围构造请求，适合验证“检索指标 → 确定观测范围 → 获取结构化数据”的路径。接口输出保存为带查询和来源记录的数据快照，不能冒充源站原始文件。[官方文档](https://datahelpdesk.worldbank.org/knowledgebase/articles/898581-api-basic-call-structures)

已按具体实例接入 CKAN/Dataverse 门户，并按批扩展遥感和气候服务、文本语料与工程数据仓库。CKAN 接口可搜索一个站点的数据集及资源；每个实例仍需核验能力，不能将接入 CKAN 协议描述为覆盖所有政府数据。[官方文档](https://docs.ckan.org/en/latest/api/)

首期对外成立的条件是新增来源的真实端到端闭环。仅把现有三个生物连接器隐藏在“自动选择”后面，不算完成全学科设计。

## 获取与准备

“获取并准备”先展示确定的内容：数据版本、选择范围、必要文件组、大小或未知大小、实际获取条件、保存到“我的数据”。普通用户看推荐文件组合，高级用户可展开完整分页清单。双端序列、Shapefile 配套文件、影像波段、矩阵与注释都是通用文件组关系。

一次点击授权确定范围内的获取、有限重试、基础校验和有界预览，不重复询问。扩大范围、突破显示的预算、替换源版本或接受来源额外条款时才重新说明。许可原文和链接按来源记录；未声明显示未知。

下载使用独立于聊天页面生命周期的持久后台任务，关联所属会话、查找修订、候选与清单快照；详细进度和结果在右侧面板恢复，原聊天卡片保留关联回执。逐文件流式写入暂存区，验证后登记正式对象。文件目录不能静默截断；官方支持的子集查询记录全部参数。抽样、聚合、解包和格式转换保留原文件，并生成有转换记录的派生文件。

当前通用获取链路不设置单文件、整批字节数或一次获取文件数量的固定上限，用户可一次选择需要的全部文件。后台按受控并发和顺序传输处理完整选择，不要求用户手动分批；已取得文件完整保存到“我的数据”。文件写入独立持久暂存卷，按块计算摘要和保存对象，不将整份文件读入内存。传输检查实际可用磁盘空间，网络使用读取空闲超时；持续传输不因固定全程时限而终止。来源访问条件、存储容量及后续分析运行资源仍是实际约束。

文件选择器只显示当前可获取的文件数量与已选数量，支持全选和清空；展开后摘要使用当前文件列表的数量、格式和大小。来源的样本数与文件数分开表述，未知大小不计作零或完整合计，成功核验不显示为警告。数据获取面板明确区分任务数量和文件进度；获取、个人数据与聊天附件统一使用十进制 KB/MB/GB 显示文件大小。

传输片段和进度清单绑定稳定的任务文件标识，跨重试、取消和 worker 重启保留；进程间文件锁防止并发写入同一片段。来源支持 Range 且版本凭据一致时续传；忽略 Range、版本变化或无法确认版本时重新获取该文件。World Bank 的派生 CSV 从第一页重新生成，避免把不同时间的分页拼成同一快照。实际文件、来源凭据和任务完成进度保存后才清理暂存；上传成功而进度未保存的间隙通过重新核验已保存对象恢复。

获取状态与准备状态分开：

- 获取任务：等待执行、获取中、校验中、完成、部分完成、失败、已取消。
- 准备状态：待检查、可读取、格式暂不支持、缺少配套文件、准备失败。
- 本次需求：满足已核实条件、存在缺口、仍需检查。

“可读取”不等于“适合本次研究”。校验方式记录为来源校验和、压缩/格式完整性或仅本地摘要，不能统一夸称来源验证通过。某文件缺失时，已验证成功项仍可保存和使用，但依赖它的组合不能显示完整。

CSV、JSON、XLSX、Parquet、文本等先提供字段/样本预览；影像、NetCDF、GeoTIFF、序列等按格式插件逐步扩展。未知格式可以完整保存和下载，界面明确尚无内容预览。预览样本明确标注，不能代替完整数据；转换环境受资源限制，不自动执行来源附带脚本。

网络超时、限流及临时服务错误允许有界重试；认证、空间不足、版本变化和校验失败单独呈现。支持 Range 且能够确认源版本时才续传，否则重新下载。刷新聊天恢复服务端状态；用户可通过卡片或同一输入框重试明确 job_id 下的失败项，保留成功项和历次尝试记录。取消不删除已保存资产。获取成功后可下载到本机，或直接用于系统分析。“我的数据”保留已获取资产的跨会话复用能力，未通过实际可获取性核验的线索不出现在聊天结果中。

## 服务与持久模型

ChatPage 内的卡片操作与 Agent 工具调用同一应用服务。模型承担意图理解、查询扩展和有证据的说明；来源路由约束、分页、权限、状态、文件获取和完整性由服务端执行。自然语言动作先解析到会话内明确的 search_id、revision_id、candidate_id 或 job_id，再调用服务；不能用模糊结果序号作为服务参数。模型不得创造来源 ID、下载地址、许可证或样本规模。

```text
现有 ChatPage：同一输入框 + 持久查找卡片 / 候选 / 获取进度 / 准备结果
  → 会话动作与事件：显式目标标识、修订历史、状态恢复
  → DiscoveryService：意图版本、路由、查询、合并、匹配证据
  → 来源适配器：数据索引 / 仓库 / 领域 API / 网页线索
  → ResolveService：详情、版本、文件组、官方子集与获取条件
  → AcquisitionService + Worker：持久获取、校验、逐文件结果
  → DataLibrary：个人数据版本、来源与文件
  → PreparationService：有界预览、可读取性、必要转换
  → AnalysisBinding：明确版本与选择范围 → 分析沙盒
```

| 对象 | 保存内容 |
| --- | --- |
| DataSearch | 用户、所属会话、search_id、原问题、状态、幂等键；与会话历史的持久关联 |
| DataSearchRevision | revision_id、search_id、父修订、结构化意图、可见条件、候选结果快照及排序、用户选择；旧修订保留 |
| SourceSearchRun | search_id / revision_id、来源版本、实际查询、分页游标、状态、命中数与取回数、错误 |
| DiscoveryCandidate | candidate_id、所属查找修订、规范标识、数据版本、记录层级、元数据、关系、访问状态与逐字段证据 |
| AcquisitionManifest | manifest_id、会话与 search_id / revision_id / candidate_id、数据版本、文件选项、文件组依赖、子集范围、预算、摘要与校验条件 |
| AcquisitionJob | job_id、用户与所属会话、查找修订与清单快照、逐文件状态/字节、租约、历次尝试、取消意图、失败原因 |
| DataAssetVersion | 个人数据的不可变文件清单、来源、获取时间、原始/派生关系、准备状态 |
| AnalysisBinding | 会话、分析运行或待执行请求、明确资产版本、选择文件/子集快照、原始分析需求；运行开始后固定 |

Mongo 保存真相状态，Redis 用于唤醒和事件通知。Worker 原子领取任务并持有带版本的租约，支持租约过期回收；旧 worker 的结果不能覆盖取消或新的尝试。现有 RedisStreamTask 依赖进程内对象注册，不直接承担新下载任务的重启恢复。

查找和下载任务归用户，并以所属会话关联权限检查及历史恢复；任务执行不依赖该会话页面是否打开，关联会话也不决定已保存资产的生存期。获取不写入运行中沙盒；绑定分析输入时使用明确的会话、分析运行与资产版本、短期写入协调和状态校验，避免切换会话串文件。页面请求带 generation/取消机制，后端仍逐项验证所有权以及 session/search/revision/candidate/manifest/job 的归属关系。新修订和任务重试追加记录，事件回放不改写旧结果。删除聊天不删除已经保存的个人数据。

拟新增接口：

| API | 用途 |
| --- | --- |
| POST /sessions/{session_id}/data-searches | 在会话中创建持久查找任务与首个修订，返回 search_id / revision_id |
| GET /sessions/{session_id}/data-searches | 恢复本会话查找卡片及其修订、获取记录关联 |
| GET /data-searches/{search_id}?revision_id= | 获取明确修订的意图、来源执行状态及历史关联 |
| GET /data-searches/{search_id}/results?revision_id=&cursor= | 分页查看明确修订的统一结果 |
| POST /data-searches/{search_id}/refinements | 携带 base_revision_id 细化需求并追加新修订，保留旧记录 |
| POST /data-searches/{search_id}/continue | 携带 revision_id，沿该修订的查询游标继续检索 |
| POST /data-searches/{search_id}/candidates/{candidate_id}/resolve | 携带 revision_id，获取详情及可分页文件/子集选项 |
| POST /acquisitions | 按 session_id / search_id / revision_id / manifest_id 和幂等键创建后台任务，返回 job_id |
| GET /acquisitions/{job_id} | 在原聊天中恢复任务、历次尝试与逐项结果 |
| POST /acquisitions/{job_id}/cancel 或 /retry | 取消明确任务或只重试其失败项，保留成功项与记录 |
| PUT /sessions/{session_id}/data-context | 扩展现有接口，设置下一轮明确资产版本；不能改写运行中 AnalysisBinding |

任务事件携带所属会话、search_id / revision_id 或 job_id，支持断线续接和幂等回放，轮询读取作为恢复路径。查找/获取事件不占用或关闭聊天输入；待执行分析要求也有持久记录，不依赖组件内存等待。权限与来源范围检查放在共用服务，所有旧工具经过同样检查。来源内容均视为数据；网页任意地址不能直接进入下载器，需解析与受控地址验证，重定向也重新检查。宿主路径继续受 DATASET_HOST_PATH_ALLOWLIST 和只读挂载约束，浏览器只接触不透明标识与公开来源。

## 迁移与交付顺序

当前代码可复用连接器注册/参数验证、来源客户端、ZIP/MD5 等校验、FileService、MinIO/GridFS、个人数据留存和现有预览。现有候选偏向 NCBI，新增通用模型，不把跨学科结果伪装成 NCBI 记录。

1. **基础一致性。** 修复会话文件竞态、旧工具来源范围、文件目录截断与部分失败反馈；新增查找/获取持久对象、worker、统一服务及兼容入口。
2. **首期完整产品。** 在现有首页和 ChatPage 中交付需求提取、自动选源、持久查找卡片、候选与证据、获取进度、准备结果、DataCite + Zenodo + World Bank 实际接入、实体数据核验、分页续查、获取到个人资产及明确版本的分析交接。同一输入框完成细化、获取、取消、重试和分析；不新增查找页面或获取任务导航。至少 CSV/JSON 和现有可用格式贯通，修订历史、下载刷新/重启恢复及运行中分析输入隔离随首期交付。
3. **扩展数据形态与规模。** 增加门户实例、遥感/气候、语料与工程来源、官方子集、更多格式准备和认证。当前已实现持久分块传输、条件续传及存储不足反馈；后续扩展组织配额、容量管理和更多来源的恢复能力，持续核对实际存储与分析运行资源。

HomePage 的“查找开放数据”进入同一个聊天流程；ChatPage 扩展持久任务卡片和显式引用上下文，继续复用现有输入框。旧 ConnectorResults 历史卡通过兼容入口继续工作，并绑定原会话及原检索记录；新卡按 search_id / revision_id / job_id 读取统一状态。MyData 与个人数据侧栏继续负责资产预览、选择和跨会话复用。新流程不再要求成功 ToolEvent 才能选择数据，卡片按钮和聊天指令也不再分别维护获取状态。现有最多 32 文件的分析输入限制需与资产文件组、物化策略同步处理，首期超限明确提示，不静默丢文件。

## 验收标准

用固定问题集覆盖经济社会、地球环境、工程物理、人文文本、生命科学。逐例记录预期条件、允许的数据形态及已核实来源；分别衡量找到相关候选、取得实际内容、满足分析输入要求，不能只统计搜索命中数。

当前[跨学科评测夹具](../backend/tests/fixtures/open_data_relevance.json)包含语言语料与同名地域/动物的区分、空气污染与儿童健康的完整数据和组成数据、成人临床与动物分子实验、教育就业的国家年份约束、人类虹膜与 Iris 花卉等正反例，也覆盖明确排除目标内容的记录。`test_open_data_relevance.py` 使用受控模型响应检验原问题与证据绑定、非法输出、约束矛盾、超时、取消和批次边界；这些单测不代表真实模型语义准确率。夹具可另用于实际会话模型回放，模型、输出和未通过项需分别记录，不能把有限样例推广为全学科准确率。

`test_open_data_query_syntax.py` 检验多词 `AND`、引号/字段/布尔保留、全部 CKAN 实例的请求契约及分页绑定；官方只读复测确认瑞士目录中的 `Tibetan language` 不再仅因 `language` 返回姓名数据，且正常主题仍可检索。服务测试覆盖先判断后探测、稳定排序、历史证明失效、待确认重试及已保存文件保留；真实 Vue 浏览器夹具覆盖跨来源顺序、无关项隐藏、匹配依据、本地展开与继续查找区分、待确认提示，以及原获取面板与手机交互。官方查询计数和有限回放只描述测试时的观察，不构成所有来源、所有时间都有效的保证。

- 新用户不知道来源名称也能在一个聊天窗口中完成查找、理解候选差异、获取和开始分析，不需要独立查找页面或获取任务导航；未覆盖或需申请的场景准确显示边界。
- 中英文语义扩展保留原意；国家、时间和粒度等硬约束不被自动改变。相关网页不被标成已下载数据。
- 新接入来源至少两条真实获取路径贯通，并有一个多来源组合检查用例；检查版本、许可字段、元数据与下载内容是否一致。
- 多来源去重、版本区分、更多结果、单源失败、无命中和条件细化都有独立验证；细化追加修订，旧搜索、候选选择和获取记录仍可从聊天历史访问。
- 同一会话同时保留多个查找卡片与修订时，按钮和聊天指令均操作明确 search_id / revision_id / job_id；不能按最新卡片猜测“第二个”“重新下载”，目标不明时不执行获取或分析。
- 查找、获取和准备期间输入框可继续使用；通过同一输入框细化、获取、取消、重试和分析与卡片操作产生一致状态，不重复询问已明确授权的动作。
- 刷新、切换会话、重复提交、worker 重启、取消、429、断网、部分文件失败均不丢历史修订、获取记录或成功项，不误报完成；在所属聊天恢复正确卡片，旧响应不能污染新会话。
- 配套文件不齐、校验失败、未知格式、空间不足、源版本变化和来源访问限制给出真实状态及可执行下一步；不因旧版固定字节上限排除可获取数据。
- 分析使用明确资产版本与文件/子集快照；新检索、获取完成和新的聊天指令不会改变运行中任务，下一轮分析要求及版本选择可以恢复；删除会话保留已保存资产，“我的数据”可跨会话复用；所有入口执行一致的权限、归属和来源限制。
- 服务代码实施后执行 AGENTS.md 规定的前端类型检查/构建、后端与沙盒测试、Compose 校验；部署只更新受影响的 DataLab 服务，并核对真实获取和分析行为。

自动检索目录已在早期跨学科仓库与领域接口之外按批扩展，当前可用范围以来源注册表的启用状态及运行时核验为准；原有 NCBI Datasets 基因组连接器另外保留。未接入仓库与通用网页不属于当前自动获取范围。通用获取已通过单文件超过 64 MiB、批次超过 128 MiB 的真实流式读取测试，并覆盖已知及未知大小、重启、取消和保存检查点恢复。可获取性核验仍有候选并发、抽样字节及等待时间预算，这些是搜索响应边界，不是完整下载的大小限额。旧版 NCBI 基因组专用获取工具仍执行其清单与计划声明的真实限制，不能宣称所有旧工具都已解除限制。可获取文件子集与整个数据集必须区分，不能将取得部分文件称为完整数据集。

## 来源底座与分批接入

`open_data_registry.py` 是来源能力的单一目录：登记学科范围、检索语言、协议、文件获取方式、认证方式和启用状态。自动检索、手选连接器、查询规划与 Agent 的只读操作白名单从同一目录派生。登记不等于上线；关闭的来源不进入选择器或自动检索。NCBI 原有连接器继续保留。

查询规划只为允许范围内可执行的来源生成检索词，并随查找任务持久保存；同一规划版本的翻页、重试和 worker 恢复复用原词。手选范围不能被模型扩大或替换；不能忠实执行的来源记录原因，不用无关查询凑数。跨来源去重同时要求 DOI 与已核验文件的仓库身份一致；不能仅凭标题、相同样本内容或 DOI 推断不同版本相同。DataCite 按已启用仓库的 DOI 前缀检索，并解析到已登记的实际托管仓库。DOI 只映射到注册的仓库标识，原站清单仍重新核验；不会根据索引返回的任意页面 URL 发起下载，也不会把索引版本号当作原站文件版本。

首批上线 Harvard Dataverse 与 OpenML。Harvard 按发布版本解析文件、使用 `format=original`，不替换成平台转换后的表格；OpenML 使用官方站点全文检索并获取发布的 ARFF。两者共用现有核验、流式获取、断点恢复、来源回执与个人数据保存流程。下载跳转逐跳校验已登记的具体文件路径和存储桶，临时签名地址不返回浏览器，源许可随文件回执保留。

Figshare 适配器已具备合同测试，但当前主机与部署出口的检索接口返回 403，保持关闭；Dryad 匿名元数据可用，文件 API 实测需要 bearer token，保持关闭并标记为需要认证。它们均不计入已上线数据源。启用前必须验证真实检索、文件核验和完整下载，而非只修改注册开关。

| ScienceDB 科学数据银行 | 国内跨学科科研数据，中英文主题 | 明确公开、免费且无需登录的发布版本原始文件；递归读取公开文件目录 |
| Borealis | 加拿大多机构跨学科研究数据 | 已发布版本原始文件，保留源许可与校验和 |
| DataverseNL | 荷兰高校与研究机构数据 | 已发布原始文件，支持原站 SHA1 等校验和 |
| Recherche Data Gouv | 法国国家研究数据仓库 | 已发布原始文件；不将外部收录元数据作为可获取数据 |
| PANGAEA | 地球、气候、海洋、环境与生态 | 原站声明开放的原生 TAB 数据表；无数据表的集合页不展示 |
| GBIF | 物种分布、分类名录与采样数据 | GBIF 官方托管及 France、Norway、Spain、Portugal 已支持节点的原始 Darwin Core 归档 |

ScienceDB 使用 [官方公开接口](https://www.scidb.cn/api/sdb-openapi-service/sdk/README.md)核实权限与版本，再从官方公开文件目录获取原文件；GBIF 使用 [Registry API](https://techdocs.gbif.org/en/openapi/v1/registry-principal-methods)及登记的托管节点，未经接入的外部发布者域名不直接访问。Dataverse 实例遵循 [Data Access API](https://guides.dataverse.org/en/latest/api/dataaccess.html)，PANGAEA 遵循其[数据访问说明](https://wiki.pangaea.de/wiki/Data_Access_and_Reuse)。跨节点跳转仍逐跳校验精确域名和文件路径。

不选择连接器时，全部已启用来源进入查询规划的候选范围，系统按完整研究需求选取相关来源并行检索，并非逐一请求所有来源；选择连接器后只在所选范围内执行忠实可运行的查询。规划失败的自动模式保守选择少量通用仓库；手选模式保留所选范围并检查必要观测参数，不能借失败启用无关默认观测。接口的来源数量上限已随扩展提高，避免选择当前全部来源时被旧的 12 项上限拒绝。

连接器弹窗只显示官方 Logo、名称和选择控件，支持按名称过滤和清空选择；详细能力与限制继续放在数据源管理页。图标存放在 `frontend/public/images/connectors/`，`sources.json` 记录官方来源和摘要，界面加载不请求第三方图标站点。原生复选框、单选框和交互控件使用统一绿色焦点提示，保留键盘可见性；数据图表与官方标志保留自身颜色。

下载核验新增 SHA1、SHA512，与已有 MD5、SHA256 一起保留原站摘要算法；断点恢复和已完成缓存仍重新核验本地内容。无源摘要的数据只声明本地计算的 SHA256，不声称完成源校验和比对。

后续按批推进：继续核实国内 NADC/LAMOST、公开 GSA 的接口与授权接入，再扩展 SDMX 统计源、气候遥感和更多仓库实例。USGS 需要明确时间、地区和震级的结构化查询；DBnomics 需要处理数据集与时间序列的分层检索，不能把任意前几条观测值当作完整数据集。需要账户、许可确认、申请或仅允许远程分析的来源，先实现相应授权或任务机制；不作为匿名可下载来源展示。每批保留同一聊天入口和右侧获取面板，不新增工作区。

大文件落存使用流式 multipart，分片大小随存储协议要求调整，读取缓冲保持 1 MiB，并逐片验证 Content-MD5；取消会停止传输并清理未完成分片。已保存文件的浏览器下载支持 HEAD、Range/If-Range，通过有界存储读取交付；分析输入的不可定位流使用磁盘暂存，避免完整读入内存。真实 MinIO 已验证 65 MiB + 17 字节上传、回读及完整 SHA-256 一致；TB 级界面与分片策略测试为合成测试，不代表实际传输了 TB 级数据。
