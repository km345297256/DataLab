# 通用分析执行可靠性

本次改动适用于一般分析脚本、报告和数据处理流程，不引入特定学科的统计规则或自动科研认证。

## 文件修改

编辑已有小型文本文件时，先使用 `file_read(include_version=true)` 获取完整文件的 SHA-256，再以 `file_apply_patch` 提交一组替换。所有替换针对同一原文，必须满足基准版本、匹配次数及不重叠要求；可选择 Python 或严格 JSON 语法检查。检查通过后同目录原子保存，无效果修改保留 mtime。

这是协作文件 API 的并发保护。外部程序不遵守目录锁时，系统检查能够观察到的版本变化，但不声称提供面向任意外部写者的操作系统级 CAS。输入挂载保持只读，符号链接、硬链接及不可写目标不能用于补丁写入。版本读取和补丁文件限制为 8 MiB，普通源数据预览不自动读取全文件。

## 失败诊断

已确认的程序首次失败直接附带有限执行源码上下文、错误位置与版本信息，供下一次模型决策使用。信息来自私有执行记录；未知执行不生成成功或失败证明。不会为生成诊断自动读取更多文件、调用额外模型或重跑程序，也不会把源码凭据公开到页面。

## 阶段依赖与结果集合

已有 `StageCache.run` 增加 `upstream={"fit": fit_result}`，将上游阶段标识和派生文件摘要纳入下游身份；复用前检查派生文件版本。报告阶段失败不使已完成的拟合阶段失效，上游变化则下游身份随之变化。只适用于显式声明全部依赖的阶段，短任务继续一次执行。

后端交付时生成拥有用户和会话归属的 `result_set`，绑定输入版本范围、交付对象和观察到的执行版本。工作文件与保留对象不同则标记 `retained_prior_version`；无法确认的版本标记 `unconfirmed`。模型提供的同名记录会被覆盖。执行与文件同属一个步骤仅是关联证据，不证明生成因果关系；不支持的依赖关系仍为未知，不据此自动重算或判定科研结论。

## 展示与技能创建

文件时间线使用“文件保存记录”，分别统计写入、局部修正、追加，以及失败、沿用版本和未执行状态。技能创建复用已有检查点，增加安全阶段进度记录；创建失败后直接提供恢复入口，不再调用科研建议模型。进度事件不会把未完成草稿当作成功技能。

## 部署与边界

保持 `datalab` 分支和 DataLab 独立服务。沙箱以当前运行镜像为基础，仅更新本次文件 API 和分析辅助模块，保留科研依赖；Jupyter 与存储服务保持原镜像及卷。原始输入不复制为会话缓存，交付仍使用对象存储引用。
