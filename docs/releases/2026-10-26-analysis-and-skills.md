## 2. 分析代码执行路径

### 2.1 移除 Quicklook 专用链路

`dataset_quicklook` 工具、沙箱脚本 `dataset_quicklook.py`、镜像中的 `ai-dataseek-quicklook` 命令，以及对应的专用编排、摘要与结果合成逻辑已移除。工具目录和前端新调用的展示映射同步更新。

这意味着宽泛的“探索数据”“画图”请求继续由执行 Agent 根据实际输入和用户目标选择注册能力或编写程序，不能再调用旧工具获得固定的 profile、图表与 manifest 套装。`dataset_unpack`、注册科学工具和自定义程序执行仍保留；需要解压时复用一次解压返回的最终文件清单。

历史记录中可能仍有旧工具名称，前端对旧合成控制台记录保留部分展示兼容。历史记录存在不代表旧工具在新运行时仍可调用。

### 2.2 保存程序后观察真实执行结果

保存的 Python 分析程序继续通过 `program_run` 执行，传入绝对脚本路径、工作目录和字面参数数组。执行策略强调保留程序自身退出码，避免 `| head`、`; ls` 或 `|| true` 等外层命令掩盖分析失败。

对已有 Python 脚本，先取得完整文件版本，再通过 `file_apply_patch` 提交有版本约束的修改，并使用 `syntax_check="python"`。语法无效的候选内容不应覆盖原保存版本。补丁保存成功与程序执行成功是不同事实。

程序开始前应检查必要的输入结构、行身份、形状和有限值。低成本计算可以把这些断言放在同一次运行开头；昂贵流程若核心操作存在不确定性，可先用小型代表性或合成案例验证该操作，再复用已检查实现。已掌握的事实无需反复探测，失败也不能通过更换用户指定方法或删掉断言来伪装成功。

分析执行的观察窗口不等于任务总时限。等待返回仍在运行时继续观察原操作，未知状态不授权重复启动。具体生命周期和取消行为见 [AnalysisJob](../analysis-jobs.md) 与 [运行恢复](../analysis-runtime-recovery.md)。

## 3. `python_inspect`：查询已安装的实际接口

### 3.1 返回什么

该工具接收一个点分模块名以及至多 8 个相对点分属性名。例如查询某统计结果类型的比较函数时，应阅读其实际签名和 Returns 文档，再决定如何接收元组或字典结果。

观察结果包含：

- Python 版本及能够确认的分发包版本。
- 模块是否导入成功、属性是否存在或不可观察。
- 可以获取的函数或类签名。
- 有长度限制的文档文本，长文档尽量保留 Returns、Yields 和 Raises 信息。
- 明确的截断状态；无法取得签名时报告不可用，不猜测参数。

实现对最终 JSON 字节数设置上限，避免将大量接口文档灌入模型上下文。异常只返回错误类型等有限信息，不回传原始异常文本、任意属性值或文件路径。包导入产生的 Python、原生和退出时输出不会混入结构化观察正文。

### 3.2 执行与限制

查询在任务沙箱中通过正常程序执行器进行，不在后端 API 进程内导入用户选定模块。它不调用目标函数，不构造目标实例，也不执行所询问的分析；类或实例属性遍历尽量使用静态观察。

但 Python 导入可能运行初始化代码，模块的动态属性也可能有行为。因此它被声明为可产生沙箱读写和网络影响的工具，不能称为纯只读探针。库名和属性名只做语法、长度与数量校验，不建立允许或拒绝的库/API 清单。

该元数据查询有独立的 20 秒时限，取消和超时处理针对同一个查询操作。这个时限不改变普通分析的运行策略。工具查询成功也不意味着目标包一定导入成功：应继续查看观察中的 `state`、成员状态和返回文档。

旧分析容器可能没有新助手。此时返回“查询助手未安装”的明确结果；确有需要时，可以在可写任务空间保存小型接口查询程序并用 `program_run` 运行。不应为一次查询重建既有会话、伪造系统助手或重跑已经完成的分析。

### 3.3 界面表达

时间线显示“正在查询 Python 接口”和“Python 接口查询已结束”，简要列出模块与属性。控制台说明这是 API 观察，没有执行数据分析，不显示一个合成的成功退出码来暗示分析完成。详细内容进入私有溢出结果时，普通控制台也不暴露其定位信息。

## 4. 可选统计助手与结果一致性

这些组件是可观察的运行时能力，并非所有分析必须采用的框架。普通代码策略仍以完成当前需求为目标；本批不宣称加入助手必然减少模型错误或提高所有任务成功率。

### 4.1 行守恒与索引对齐

`datalab_analysis` 补充了更明确的 API 说明：

- `RowPartition.verify(retained_ids)` 返回包含 `passed`、原始行数、保留行数和排除原因计数的证据字典，不是保留行 ID 列表。调用者必须保留自己的 `retained_ids`。
- `aligned_groups` 返回“分组标签 → NumPy 数组”的字典。Series 输入需要与保留行身份具有完全相同的顺序索引；不能把过滤后的残差与新建 RangeIndex 静默对齐。
- 缺失分组需要明确处理，不能通过分组操作悄悄丢行。数组输入按位置处理，调用方仍须提供真正的原始行身份。

### 4.2 三个具名统计接口

| 接口 | 主要检查 | 不能替代的判断 |
| --- | --- | --- |
| `nested_ols_f_test` | 同一响应、同一有序样本、嵌套设计矩阵、秩与自由度，返回明确的 `F`、`p`、`df_num`、`df_den` | 任意模型都适用经典嵌套 OLS F 检验；稳健协方差或不兼容模型不会被静默改写 |
| `linear_contrast` | 对比向量维度、有限值、协方差与所用分布约定，返回具名结果 | 研究问题、对比方向或因果解释是否合理 |
| `residual_levene` | 从拟合结果读取真实残差，核对行身份、分组及显式声明的组别 | 以组内响应减均值替代模型残差，或据单个检验证明完整模型有效 |

无标签数组拟合的完整模型与受限模型必须分别给出 `row_ids` 和 `restricted_row_ids`。样本数相同不能证明两者来自同一组且顺序相同的观察。不能把库函数返回的“自由度差”误写成分母残差自由度。

不兼容方法、退化数据或不一致的返回值会明确失败。修复应针对真实原因；若验收条件自身错误，应保留证据并解释修订，不能将观测结果直接改成期望值。

### 4.3 从同一结果快照交付多个成果

`datalab_results.ResultBundle` 将非空、有限、JSON 兼容的结果对象冻结成一个版本。修改原字典或 `snapshot()` 返回的副本不会改变该版本。

它提供 JSON、CSV、支持的折线/散点 PNG 图和报告事实片段导出。表格会核对列、行与单元格；图形检查受支持的实际绘图对象；报告中的受控事实来自同一冻结数据。每个产物记录字节摘要，`verify()` 会再次核对文件身份与受控内容。

必须区分以下边界：

1. 成果与同一计算结果一致，不代表上游计算科学正确。
2. 绘制了给定上下界，不代表这些界限就是 95% 置信区间。
3. 报告的自由解释文字没有获得语义核验；返回状态明确标记科学有效性与自由文本未评估。
4. 写完报告后新增或改变表格、图形，可能使报告产物清单过时，需要重新生成报告并验证。
5. 文件被修改、丢失或重定向后，不能沿用旧验证结果。

该组件不自动上传、不复制输入、不要求额外交付 manifest，也不会为原始下载文件换名后把它视为新成果。只生成当前用户要求的输出；未支持的格式可使用正常工具。实际持久交付仍以对象存储文件引用为准。

## 5. 技能创建保留历史与方法依据

### 5.1 历史不是最终方法的自动合集

技能提炼现在按用户对话轮次建立有顺序的分析历史，排除只包含技能创建操作的轮次。当前分析仍须满足既有的完成与归属检查；不能因为最新请求失败，就自动退回较早成功分析来掩盖问题。

历史来源区分 `completed`、`failed` 和 `incomplete`，并记录已被替换的目标、步骤版本和公开讨论。未完成或失败轮次不会被包装成已执行的成功步骤。供模型使用的是经过隐私处理的公开方法和证据摘要，不是原始工具负载、私有执行回执或隐藏推理。

方法契约新增两类明确的历史排除：

- `superseded`：被后续来源替代，必须给出更晚且被保留的替代来源。
- `outside_scope`：历史内容不属于当前技能范围，不伪造替代来源。

这些排除只适用于具有有效时间顺序的历史来源。结构有效仍不等于语义正确，独立方法审查继续判断排除是否合理。

### 5.2 成功程序是方法参考，不是科学认可

来自完成轮次的原生 `program_run` 证据可以关联到当前或历史轮次，并按同一脚本路径的执行顺序描述前后版本。原始路径和摘要仅用于后端关联，模型收到可移植引用编号与顺序信息。

程序参考投影保留结构常量，以及被请求/方法来源明确支持且不含私密信息的标量。观察数据、没有来源支持的字面值、注释与直接字面集合会移除或参数化。私有局部绑定可以一致改名；非私有外部 API 保持原义。

私有成员名无法安全保留时，会标为需要重新绑定的成员占位符，并记录读、写、调用等角色。占位符不是已知 API；生成脚本必须从原方法契约与当前输入重新绑定，再独立审查。此类参考不可直接执行，也不表示历史程序退出成功就获得科学认可。

方法依据无法安全转换时，技能创建返回明确失败，原分析成果保留。该失败不再提示简单重复重试即可恢复；需修复转换问题或补充有效分析依据。

## 6. 先声明接口，再生成与验证脚本

新工作流使用版本 2 的实现计划，要求每个待生成脚本具有明确接口契约：

- 命令行选项及别名、类型、必填、默认值和参数行为。
- 绑定到选项的输入格式、字段或容器结构。
- 输出是一个文件还是一个目录，以及目录内具体输出文件。
- 缺失、null、空值和零值的处理语义。
- 输入文件名只是定位绑定，还是参与标签、日期、分组、筛选等分析含义；未确定时保持 `unknown`。

新契约要求明确的 `--input`、`--output` 绑定。JSON 需声明根结构，CSV 需明确列名或动态列约定；结构声明不容纳参考答案或计算结果。

生成实现、候选执行与盲参考验证使用同一预声明接口。静态检查可以拒绝已证明的命令行、输出路径或字段冲突，但不能根据候选源码反过来重写契约，也不能把动态结构“未发现冲突”视为已经验证，实际执行检查仍然必要。

旧版本 1 配方和已保存审查继续兼容。缺失必要接口的版本 2 内容不会静默降级到从源码猜测接口的旧路径。本批没有要求迁移或重写全部历史技能。

## 7. 局部修订与隐私处理

### 7.1 宿主核实的修订范围

方法审查可返回 `implementation`、`workflow` 或 `none` 修复范围，包含受影响要求、负评来源和脚本路径。宿主检查这些编号与真实脚本声明、覆盖关系是否匹配，不能仅凭模型说“实现问题”就放宽范围。

只修改指定脚本的条件包括：涉及的负评要求完整覆盖、来源级负评包含该来源所有保留要求、目标脚本确实承担相应要求、没有需要改变来源纳入或排除决定的设计问题。范围不完整、接口或工作流需要改变时，仍走工作流修订。

源码修订只对现有脚本应用精确定位的非重叠替换，并要求实质可执行代码变化。仅修改注释或文档字符串不算修复完成。每次修订后仍检查整个包并重新进行独立方法审查；局部定位不是批准，也不抹去既有负面审查事实。

### 7.2 按数据角色减少错误拦截

隐私检查继续扫描真实身份、宿主路径、源文件名、凭据和 URL。本批细化了几类受控语法和角色：

- 无默认值的纯类型参数声明不等于写入真实凭据；字面默认值、注释和已知敏感值仍扫描。
- 只有请求范围内、结构完整的合成验证计划，其 JSON 输入数据才可承担人工身份数据角色。普通字典中出现 `user_id` 字段不自动获得例外。
- 合成身份角色不覆盖解释文字、期望结果、真实凭据、路径或 URL；已知真实私密值优先拦截。
- 只有当前验证目标的明确 JSON 指针及其冻结字符串比较可作为审查语法；不能借此放行额外路径后缀或另一个阶段的字段。

初次合成测试计划中的文件名与真实源文件名冲突时，仅在接口已被独立审查确认为 `binding_only` 后，宿主才可分配可移植的夹具名称，并同步准确的 `{input:...}` 绑定。普通数据字符串、键、期望值和已经冻结的计划不参与改写；文件名承载分析含义或角色未知时保持原状并走正常检查。

工作流隐私修复也限定在允许的文本坐标。接口选项身份、默认值、结构键、类型和要求关联不能通过“隐私修复”顺带改变。

## 8. 阶段状态与持久化兼容

方法审查的结构化回复返回后先报告 `response_received`；宿主完成语义判定后，再报告 `accepted` 或 `revision_required`。前端对应显示“审查结果已返回”“审查通过”“需要修订”。

从检查点复用内容时仍需区分取得已有回复与通过审查，不能因为复用成功就显示科学审查通过。持久化变更记录位于 [技能审查状态契约](../persistence/2026-10-26-skill-review-verdict.json)；旧技能配方和审查字段的兼容由可选字段及版本分支维护。

### 9.3 真实模型验收独立进行

真实模型分析代码验收不属于自动 pytest 发现，使用 [验收运行说明](../../backend/tests/acceptance/README-analysis-code.md) 中的显式入口。它调用原生执行 Agent、模型驱动、文件工具和程序执行器，使用一次性沙箱与只读合成输入。

基线和候选必须使用同一组任务、夹具、验收器、模型路由与配置、科学依赖、基础镜像、重复次数及实验时限。源码快照与助手版本是被比较的改动，来源摘要单独记录。不完整执行记录、缺少真实模型调用或条件不一致时，不形成可比性能结论。

指标区分首次程序执行、失败后的修改恢复、模型调用次数与耗时、总耗时以及独立结果检查。接口查询不计为分析程序成功或恢复。退出码成功不能抵扣数值或多成果一致性失败，少量合成案例也不能证明所有真实任务的错误率下降。

真实模型运行会调用已配置服务，产物和报告保存在私有本地目录。应显式安排该验收，不将真实凭据、原始会话或本地报告提交到仓库。

### 9.4 用户流程验收

1. 用小型 CSV 发起有明确方法与成果要求的分析，确认没有调用已移除的 Quicklook 工具。
2. 在接口确有不确定性时观察 Python 查询卡，核对它没有被标为完成分析；环境不变时复用观察结果。
3. 覆盖过滤中间行、分组及模型比较，验证行身份、自由度和缺失值规则未发生静默变化。
4. 使用多个成果时，修改一个已登记产物，确认旧的一致性回执不能继续作为有效依据。
5. 在多轮方法修正后创建技能，核对保留的方法与明确替代的旧方法，以及脚本输入输出声明。
6. 用明确实现缺陷触发修订，确认只修改授权脚本，修订后重新审查，阶段状态没有提前显示通过。

这些步骤描述验收目标；是否通过必须依据实际运行记录填写。

## 10. 升级与部署注意事项

本批涉及 backend、frontend 和 sandbox 镜像内容。沙箱新增助手、移除旧命令，不能仅更新前端就认为执行环境已升级；应构建需要更新的镜像，并在新任务中确认实际运行版本。未变更的 Jupyter 镜像继续复用。

已有沙箱不会原地获得新助手，不应为了让历史任务显示新能力而重跑已完成分析。模型看到的运行时能力目录来自实际观察，缺失助手按明确错误与兼容路径处理。

更新仍使用 `datalab` 项目、`datalab-*` 镜像与隔离网络/数据卷，默认访问端口 `10030`。已有受控发布快照时遵循 [生产发布流程](../deployment.md#7-已启用发布快照的生产部署)：`production --build` 只接受 frontend/backend，沙箱镜像须按对应镜像准备与快照流程纳入，不把它当成可以构建所有服务的入口。

构建前检查 Docker 可用空间，不删除数据卷。保留数据库与 bucket 内部标识，不进行隐式存储迁移。计算结果检查与技能证据处理均不改变输入只读、按范围读取对象和只交付持久结果引用的边界。
