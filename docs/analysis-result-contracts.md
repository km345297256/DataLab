# 可执行的分析结果检查

本轮补充的是计算与输出的一致性检查。运行退出码、文件完整性、数值检查和科学结论有效性是不同事实；任何一个辅助函数都不能证明任意分析方法科学正确。现有成果上传、只读对象输入和阶段缓存边界保持不变。

## 计算中的检查

新沙箱的 `datalab_statistics` 提供三个可通过 `python_inspect` 查询的小型接口：

- `nested_ols_f_test`：经典嵌套 OLS 比较，核对同一响应、样本身份、设计矩阵嵌套和自由度，并返回明确的 `F`、`p`、`df_num`、`df_den`。库函数返回的自由度差不能写成分母自由度。
- `linear_contrast`：核对对比向量维度、有限值和拟合结果的协方差/分布约定，输出具名的对比结果。
- `residual_levene`：从指定拟合结果取得真实残差，复用行身份对齐检查并核对声明的分组。组内响应减均值不能冒充模型残差。

拟合时优先保留原始 Pandas 行索引。如果两个模型均由无标签数组拟合，调用 `nested_ols_f_test` 必须分别传入 `row_ids` 与 `restricted_row_ids`；函数不会凭样本数相同就假设两边行顺序一致。只有实际选定的样本和顺序相同时，调用方才可显式为这两个参数使用同一组保留行编号。

这些函数检查已支持计算的具体条件，遇到不兼容方法或退化数据会明确失败，不偷偷换模型。其他库、API 和分析方法仍可使用；需要根据其方法建立相应检查。不要为使用某个辅助函数而改变用户要求。

默认编写代码策略保持简单直接。能力目录仅说明可选组件已安装，不要求普通任务改用框架或增加探针。初轮真实回归没有证明优先使用助手能减少报错，因此未将该建议设为全局默认规则。

检查失败时修复实际原因。若原有验收条件本身有误，应保留证据、解释修订含义，不能将观察结果直接改成期望结果，也不能删除失败检查来宣称通过。

## 同一份结果生成多种成果

`datalab_results.ResultBundle` 对有限、JSON 兼容的计算结果创建冻结快照。后续修改原字典不会改变已绑定结果。

它从同一快照写出 JSON、CSV、支持的折线/散点图和报告事实片段，检查实际 CSV 内容和图形对象，记录产物字节身份。最后调用 `verify()`，重新核对产物和受控事实片段。核验失败不能沿用先前的通过声明。

调用者提供的上下界只能证明实际绘制了这些界限，不能自动证明它们是 95% 置信区间。自由撰写的解释也不会因为与受控事实片段同在一篇报告中，就获得语义核验。组件明确报告这两类限制。

该组件不自动上传，不复制源数据，不要求额外交付清单文件；只生成用户本轮要求的成果。不能用它给原始下载文件改名后充当新分析成果。未支持的图形与格式仍使用正常工具，并进行与该成果相关的实际检查。

## 端到端回归

固定合成案例用于检验行守恒、索引对齐、模型比较自由度和多成果一致性。确定性测试先验证独立预期值；真实模型测试另行运行原生执行 Agent、文件工具和程序执行器，禁止将固定脚本测试冒充模型成功率。

基线与候选版本必须使用同一组任务、数据、验收器、模型配置及科学计算依赖。应用代码和新辅助函数版本是允许比较的改动，均记录来源摘要。配置不一致或记录不完整时，不输出可比的性能结论。

分别记录首次程序执行成功、发生失败后的恢复、模型调用次数与耗时、总耗时，以及独立结果检查是否通过。程序退出成功不抵扣数值或成果一致性失败。小样本结果只描述本次案例，不推断所有用户任务的错误率。
