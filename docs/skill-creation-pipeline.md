# 技能创建流程

技能创建从当前账户的一轮完整分析中提炼方法，产物先保存为个人草稿。用户可以查看介绍、下载技能包，再决定是否添加到技能库；生成过程不自动安装。

## 模块职责

实现位于 `backend/app/domain/services/skills/skill_creation/`。旧 `session_skill_creator.py` 仅保留兼容导出，不再实现业务流程。

| 模块 | 职责 |
| --- | --- |
| `intent.py` | 识别创建意图，排除否定、引用及未来计划 |
| `evidence.py` | 校验归属，选择已完成分析回合，只读取可信成功程序依据 |
| `privacy.py` | 根据来源类型收集敏感标识，逐字段脱敏与检查，输出安全位置诊断 |
| `models.py` | 参数、方法步骤、输出、脚本及实现计划的结构契约 |
| `gateway.py` | 模型调用、结构校验、有限定向修复及安全进度 |
| `model_policy.py` | 按精确官方服务与模型匹配原生容量与技能创建推理配置，避免隐式截断和共享配置污染 |
| `schema_repair.py` | 对完整测试计划的错误结构字段做受限修复，保留正常断言和输入 |
| `source_response.py` | 接收完整 Python 源码，由宿主绑定脚本身份与调用接口，不要求代码嵌入 JSON 字符串 |
| `implementation_revision.py` | 将实现修订作为原脚本上的精确文本事务，冻结工作流和接口，全部匹配成功后一次合并 |
| `workflow_authoring.py` | 工作流只声明脚本计划，在内容项标注要求编号，由宿主编译覆盖位置 |
| `workflow_outputs.py` | 对来源可确认的历史生成产物分配新的输出文件名，在源码生成前统一工作流中的明确引用 |
| `script_authoring.py` | 长脚本的函数接口计划、完整函数生成及确定性单文件装配 |
| `checkpoints.py` | 保存账户隔离、24 小时有效的已校验阶段和待修订候选；恢复时重新校验 |
| `pipeline.py` | 方法提炼、工作流设计、脚本生成、独立方法审查和合成执行 |
| `skill_candidate_method_audit.py` | 将已确认的运行分歧定位到原要求，校验独立源码审查的来源引文与代码定位 |
| `skill_script_verification.py` | 冻结验收计划，隔离运行，协调构建、方法及普通修订和待审源码恢复 |
| `script_policy.py` | 检查 Python 语法编译和声明式调用；输入只读及输出隔离由实际运行边界保障 |
| `package.py` | 纯文档检查、覆盖约束和技能包渲染 |
| `service.py` | 组装依赖，运行流程，全部检查完成后保存归属明确的草稿 |

## 检查与修复

1. 提炼来源完整的方法要求，保留稳定要求编号。
2. 设计工作流与参数，逐项建立要求到实际实现位置的覆盖关系。
3. 分别生成声明的完整脚本，检查安全边界和方法覆盖。
4. 独立审查科学方法。方法或来源未完整保留时修订工作流；全部方法及来源已保留、但可执行实现仍有缺陷时，进入独立的实现修订。每种修订在一次创建中各有一次机会；不能要求审查者对同一内容改判。
5. 在不提供被测实现和运行结果的情况下设计声明式合成用例。
6. `skill_reference_verification.py` 独立编写并审查参考计算程序。它只接收方法、合成输入和公开接口，不接收候选预期、容差、被测实现或被测运行结果。宿主使用现有无网络隔离执行器实际运算。在最终冻结前，可以据完整、无歧义的参考计算结果修正标量预期、数量或数组长度；不修改输入、目标位置、方法覆盖或容差。结构缺失、不确定值和不完整结果直接停止，不猜测正确答案。
7. `skill_validation_review.py` 独立审查用例本身及参考计算证据，逐项核对输入类别、退出语义、科学预期和容差。每个断言都有独立记录；已计算确认的预期不能再被文字推断改写。无法确认时停止，不能让可疑验收依据驱动被测程序修改。通过后冻结计划。
8. 隔离环境执行被测脚本，检查数值、异常处理与输入未修改。允许一次脚本修复，修复稿先重新通过方法审查，再运行原冻结用例；执行后不能根据被测程序答案调整预期。
9. 保存技能草稿和验证记录。记录包含参考程序摘要、原计划与纠正计划摘要、逐项纠正及执行依据，绑定实际执行的冻结计划；参考计算、文字审查与被测执行分别记录。未通过的创建不改变原分析成果，也不安装技能。

实现修订只接收已有脚本路径、唯一匹配的原文片段与替换片段。所有匹配均基于同一份原稿，禁止重叠修改、使用前一项修改后的文本定位，或借修订改变脚本顺序、元数据、工作流、参数和输出约定。合并后重新检查完整源码、隐私、覆盖和接口；代码结构没有变化时不能再次审查。审查中的解释须对照冻结来源和方法契约核实，不能把推测当作新的科学要求。已有负面审查保留，只有实际变化后的候选可以获得新的审查。合成执行阶段已有冻结验收计划，其修复仍走专用执行修复流程，不回到这条创建阶段的修订路径。

被测技能的构建失败与科学结果分歧分别处理。参考计算及用例审查完成、计划冻结后，如果宿主确认成功用例在读取任何结果断言前发生受控的未处理异常，可以使用本次唯一的脚本修复额度修正程序构建。异常类型由固定运行包装器经独立通道返回，绑定同次执行、源码、计划及输入只读核验；打印的错误文本、无效输入拒绝、超时、环境故障、产物缺失或已有科学/结构分歧不能充当这项证据。修复模型接收原方法及其脱敏分析来源、原程序、公开接口与固定异常类别，不接收本轮合成测试的预期答案、容差、参考程序、实际观测值或原始错误文本。原分析来源可能包含此前已授权的研究总结数字，但不会混入本轮独立验证的答案。代码必须实质改变、保持原接口并重新通过独立方法审查，再执行原冻结计划；二次崩溃或后续分歧不会追加一次自动修复。验证记录保留首次构建失败及修复后的源码摘要。

这项修复使用独立阶段与检查点。参考数值尚未确认时仍沿用原有停止规则，但重建验证依据不会同时丢弃已经校验的构建修复；恢复时仍须重新校验源码和方法并实际执行，不能把缓存视作运行通过。

独立参考程序的负面方法审查同样进入实际修订流程：保留完整原审查，以冻结方法、公开接口、合成输入和上一版参考代码为依据，每次创建尝试最多修订一次。仅修改注释或说明不算代码修订，也不能触发重新投票；第二次否决停止本次创建。方法审查修订在首次执行前完成，运行后的科学结果或实际接口分歧不能触发这条生成路径。

参考审查必须覆盖实际提供的全部来源和方法要求。方法合同中已经声明排除、且盲审未提供正文的来源，可以不出现，也可以仅以“有效排除”记录；完整原审查先检查重复项，未知来源及其他判定仍会被拒绝。范围核对不删改原审查，真实的方法否决完整保存并用于代码修订。

首次参考执行另有一次严格限定的程序构建恢复：只有本应成功的用例出现受控的类型、名称或属性错误，且宿主已核验输入未改动、失败用例尚未读取科学断言，才允许修复。模型只接收原盲审上下文、自身源码、用例编号和固定异常类别，不接收原错误文本、科学预期或观察值。有其他数值或接口分歧、环境错误、超时或拒绝输入时均不进入这条路径。代码必须实质改变并重新通过方法审查、原计划和公开接口核验；再次崩溃以及后续确认执行失败都不会继续自动修复。

大规模独立审查由宿主按用例和科学目标分片，每片保留完整方法、来源与测试计划。分片划分不裁剪方法、不限制输出 token，每个 CSV 数量/字段和 JSON 目标仍必须恰好审查一次；宿主最终核对完整覆盖。重复出现的用例级判定按最严格结论合并，后续通过不能覆盖先前否决或不确定。目标顺序变化不会消除同一科学内容的已知否定结论。中文说明按有效内容校验，不用固定字数门槛拒绝完整短句。

每个审查目标直接携带宿主确定的输出文件、JSON 位置或 CSV 筛选与字段，不让审查者从大文档按位置猜测。公开输出结构通过只读语法投影提取固定键、嵌套和容器类型，抹去所有计算表达式及答案；不把扁平输出误认为可自由增加嵌套的未知结构。

对同时用于CSV表头和JSON列定义的序列，只在静态数据流能够证明其身份时公开固定字段名前缀；任意数组、数值和计算结果仍不公开。测试目标及独立参考程序必须保留这份公共表结构。静态检查提前拒绝可确认的字段冲突；无法静态证明的实现留待真实执行核对，未知不代表通过。

宿主从原公开接口编译独立的输出契约，同一次隔离执行读取实际 JSON 文件，核对每个成功用例中的固定列名前缀。契约、计划和程序各有独立摘要；接口检查单独记录，不改写原测试断言、序号或科学预期。参考计算必须先通过这份契约，才能用来确认预期；缺少、错位或未实际观察的结构不能转成可纠正的科学结果。这份记录只证明已执行用例中的公开 JSON 前缀，CSV 内容继续由原 CSV 断言和方法审查核验，不宣称已经证明所有文件之间的完整表头关系。

公开结构提取保留常见的 `json.dumps(report) + "\n"` 写法及只读别名：只允许一个已确认的标准 JSON 序列化结果添加静态 JSON 空白。动态后缀、多个文档拼接、自定义编码器和被重新赋值的序列化器不能据此证明结构。固定列前缀也不得来源于运行时可变的全局列表；未知计算保持未知，不公开原分析数值。

参考计算也可能实现错误，因此它必须经过独立方法审查和真实执行，验收还保留从未提供给生成器的固定手算回归。参考程序看到与候选预期的分歧后不能重新生成来迎合答案。只有宿主确认的完整、同语义类型标量才能修正预期；整数与有限浮点数可以互通，数值与null、布尔、字符串之间不自动转换。截断诊断、非有限数值、缺少目标或解释器异常不能转成科学结论。它增强验证依据，并非数学正确性的自动证明。

参考程序修正过的预期仍属于模型提出的计算假设。候选与这些预期不一致本身不能授权修改科学算法。若宿主确认执行成功、输入只读且存在完整实际观测，可将相关原方法编号交给独立源码审查。审查只接收原合同、来源及候选源码，不接收测试输入、预期、观测值、容差或参考程序。每项违反须指明原方法逐字引文及该程序可执行代码片段；宿主检查来源与代码定位，科学结论仍由独立审查及实际运行共同验证。只有这种有来源依据的负评可以授权一次盲方法修订；通过或不确定结论均保留“验证依据未确认”，不能据此改变候选。该修订与构建修复、普通脚本修复共享一次额度，修后先完整复审，再运行同一冻结计划。

失败执行保存最新候选、实际记录和冻结计划；修复稿在方法复审前以待审候选保存，防止中断后丢失进度。执行修复的负评不能退回整体工作流生成、重建验收标准或重新投票。单次创建调用共享一次自动修订额度；明确重试时可基于最新的真实失败继续一次实质修订，仍使用同一冻结计划。恢复待审稿时先完成其审查与执行，不在该次调用追加第二次自动修订。同一科学审查身份绑定原合同、来源、要求范围与去除注释和文档字符串后的源码。冻结执行记录失配或损坏时明确停止，不悄悄丢弃记录并回到旧候选。记录沿用私有、有时限的创建检查点，不公开测试内部材料。

参考模型只接收CSV筛选列名，不接收可能含有计算答案的筛选值；实际定位由宿主保留原条件执行。参考审查可以在解释中引用当前请求确实声明的JSON字段位置，但不能把其他路径、源文件名或身份作为说明保存。数值边界分别检查各量的定义域，避免一个正数判断同时抹去零标准误、自由度修正等仍有定义的量。

格式、隐私或覆盖检查使用同一模型边界：同阶段最多四次生成，同一诊断最多出现两次。结构修复后新发现的参数化问题仍有自己的修复机会。诊断只包含字段位置、类别及固定提示，不记录命中的私有值或模型原文。模型拒绝不可重试，服务不可用与输出不完整分别处理。

## 长输出与脚本恢复

不设置技能专属的 8K、32K 等人为输出额度。2026-10-23 核实的 DeepSeek 官方 Chat Completions 接口，在非思考模式省略 `max_tokens` 时默认输出 8K；官方 `deepseek-flash`、`deepseek-v4-pro` 支持最大输出 393216 token、1M 上下文。技能创建按精确官方 HTTPS 地址和模型匹配这些容量，适配器与请求治理使用同一份配置；兼容网关、未知模型不推测容量，已显式配置的服务能力保留。配置仅作用于本次技能调用，不修改其他任务和全局设置。参考：[接口文档](https://api-docs.deepseek.com/api/create-chat-completion/)、[模型容量](https://api-docs.deepseek.com/quick_start/pricing/)。

同一精确匹配范围内，技能创建、审查与修复的每次调用明确启用 DeepSeek 推理模式，并使用 `reasoning_effort=high`。配置覆盖普通客户端的关闭默认值，但不改变共享客户端；JSON 文档和 Python 源码请求均保留原生输出容量。真实传输层回归核对最终 HTTP 请求中的推理开关、强度、格式和输出容量，且确认普通分析调用不受影响；验收只记录这些配置与用量，不记录隐藏推理内容。参考：[DeepSeek 推理模式](https://api-docs.deepseek.com/guides/thinking_mode/)。

整份脚本一旦出现 `length` 等截断，不再原样重新生成。创建和合成修复共用独立装配层：先检查导入声明语法、签名合法性和类型引用，再固定函数名、签名、依赖、方法覆盖与入口，逐个生成完整函数，由宿主组装单个 Python 脚本。已通过函数保留，只有当前失败单元重试；不接受截断文本拼接，不通过删减方法控制长度。整包装配发现可修复的静态问题时，允许一次只替换相关函数的修复；接口、依赖和方法要求保持冻结。全部单元完成后仍须通过原有隐私、静态、整包方法审查及冻结合成验证，才能保存可下载草稿。原分析与安装状态不受未完成装配影响。

工作流设计只生成说明与脚本声明，源码由独立阶段生成。代码阶段接收完整 Python 文本或单个完整代码围栏；宿主冻结路径、用途、调用接口与函数身份，不允许模型在源码响应中改变这些元数据。兼容旧 JSON 响应时也必须精确匹配元数据。源码经过语法解析与编译检查，不通过执行源码来解析响应。结构化文档在服务明确支持时使用原生 JSON 输出模式，代码阶段不启用该模式；两者都保留服务原生输出容量。

源码生成、修复、独立参考及分函数装配在首次请求时接收同一份宿主能力协议。所有库、导入、模块导出及 API 均开放，不再使用白名单、黑名单或按函数名、属性名、变量名拦截；动态导入、公式接口、反序列化及常规库方法均可按任务需要使用。协议只说明源码形式、真实环境验证和输入输出契约。分函数装配仍须遵循 Python 语法与冻结的函数接口。缺少依赖可在任务隔离环境准备；无网络的验证环境无法安装时如实报告环境缺口，不重写基础库或改变方法来绕过。允许使用不代表已安装，也不代表科学验证通过，仍须根据实际隔离执行结果报告状态。

文档链接检查与 Python 源码按内容类型分开：Python 文件中的下标调用或相邻语句不被当成 Markdown 链接。所有源码仍接受完整隐私检查、语法与静态策略检查；技能说明及脚本用途等文档字段仍不能伪造下载链接。

空异常响应保留固定的完成原因分类；非空截断也按生成失败记入请求审计，不能因 HTTP 请求完成就标记成功。不持久化原始截断内容。调用次数与错误恢复有界，输出本身没有应用附加的长度裁剪。

完整测试计划出现可准确定位的格式错误时，宿主固定原候选与错误字段，模型只返回这些字段的修正，不重写整份测试计划。修复编号绑定原文摘要，禁止改写父节点、正常断言、预期值、容差和测试输入；误放在文件字段中的 JSON 检查位置只能原样恢复，不能换成另一个检查目标，无法确定原目标时回到完整设计；合并后重新执行原 schema、隐私、覆盖、独立预期审查和运行验证。模糊或复杂结构错误保留原完整修复路径；审查和运行后的冻结测试不能借此修改。输出文件 path 与 JSON 内 pointer 在生成接口中有明确说明。

结构有效的审查一旦给出否定或无法确认结论，不得因随后发生的隐私或覆盖校验问题再次请求改判。合法的否定结论只能进入对应的实际修订流程；包含私有信息或不完整覆盖的负面审查直接安全终止。

审查 JSON 即使破损，已经明确返回的负面判定也不能在格式重试中丢失。审查入口使用单文档、无重复键的严格解析；只读结构扫描识别已知审查字段内的否定或不确定标量。仅缺少对象闭合或末尾多余闭合、且依据固定 schema 能唯一恢复时，宿主可修复结构；字段、字符串、标量、顺序与原判定均不得变化，恢复后仍须通过完整 schema、精确目标和隐私检查，并保留原回复摘要和结构编辑证据。它恢复的是原负评，不会将其补成通过或请求模型改判。其它破损、信息截断、多文档、未知或重复字段安全停止；解释文字中的引用不作为判定。重试检查点保留同一候选的负评与恢复证据。

覆盖检查区分“必须实现的方法”和“禁止使用的名称”：禁止条件仍保留在方法合同并交给独立审查，但不会反向要求代码出现被禁止的名称；同名方法存在正向要求时仍须保留。检查直接读取实际内容文本，避免 JSON 转义改变源码词边界。

模型在实际参数、步骤、输出、验证和脚本声明中填写 `requirement_ids`，宿主按真实位置编译覆盖索引，避免排序变化导致手写指针失效。持久化包仍使用兼容的覆盖位置格式。设计错误反馈指向实际需要修改的内容与要求编号；不得通过删除方法要求、忽略错误指针或把名称说明当作实际实现来取得通过。TODO、FIXME 等程序员占位标记不作为科学方法词汇强制要求源码包含，原方法要求和独立科学审查仍保留。

所有生成文档均经过隐私检查，包括独立审查和冻结合成测试资料。已知来源文件名、身份、路径和凭证不得进入技能包。检测不拼接不同字段，不把科学标识的局部子串当身份，也不把参数引用当凭证字面量。JSON 指针与脚本启动行按其语法角色检查。

独立审查的说明可引用当前计划明确声明的 JSON 字段位置，包括该位置与有限数值、布尔值或 null 的完整比较表达式。例外只针对公开字段语法；其他字段、未声明位置、路径后缀以及已知私有内容继续拒绝。语法识别不会修改审查结论或将负面结论变成通过。

工作流设计阶段区分上传输入与历史生成产物：仅当附件具有当前账户、当前会话和宿主产物指纹，且未被选择为输入或与输入同名时，宿主可为明确声明的输出分配新的通用文件名。转换只作用于类型已验证的输出声明和允许的说明字段，不改输入条件、参数、科学数值、要求编号或脚本声明，也不改写 Python 源码。路径、复合名称、其他隐私问题或不能一致替换的引用继续按原规则拒绝；转换后仍执行完整隐私、覆盖及独立方法审查。原名与新名的对应关系仅在本地转换时使用，不进入技能包、模型请求或公开诊断。

合成验证的命令参数由独立 `skill_validation_arguments.py` 检查：输入和输出使用已声明的完整占位符，普通字符串则按原样作为参数传给程序，不按 JSON、正则、单位或路径外观推断含义，也不执行或递归展开。格式错误的 JSON 可以作为无效输入用例，由被测程序按自己的接口拒绝。只有完整的保留输入、输出占位符由宿主绑定；嵌入普通字符串的类似文本保持字面值。不可传递的 NUL、非法 Unicode 及不完整或越界的保留占位符会被拒绝。当前公开 CLI 检查仍会把以连字符开头的参数识别为选项，此类字面值尚不能保证可表达。

输入输出同址的安全负测有独立约束：仅当用例为 `invalid`、预期正常非零退出、没有科学输出断言，且两者恰好引用同一已声明合成输入时允许绑定。可追加 `output_empty`，但检查对象仍是宿主隔离的输出目录，不是输入挂载目录。执行环境保持输入只读，并核验其内容没有变化；这不允许成功用例覆盖输入。

参数化保持原输入契约：若字段映射、缩放或过滤原本位于输入 JSON，生成技能仍须从相同位置读取。用例必须使用非默认配置验证实际效果，不能额外传 CLI 参数来掩盖输入内配置失效。CSV 数量断言按 `csv.DictReader` 只计算数据行，表头不计数；只有表头的空表使用 `count=0、fields={}`，纯空文件不能冒充有合法表头的空表。可使用正数 `count` 与空 `fields` 表示只核对精确数量；零行不能同时要求字段值，数量检查也不能代替科学数值检查。

错误退出使用明确语义：来源只要求拒绝输入时，`expected_exit_code: "nonzero"` 接受正常的拒绝码；只有来源明确规定数值时才核对精确代码。超时、信号终止、解释器故障不能当作输入校验通过。提供给用例设计与审查的脚本接口仅保留调用和输出结构，移除可能包含计算答案的自由帮助文本。

无效输入的安全后置条件使用 `output_empty`：在正常拒绝、输入哈希未变后，由宿主检查整个隔离输出目录为空。文件、隐藏条目、目录和符号链接均算产物；读取失败不能当作为空。该断言不接受模型提供的路径、预期值或表达式，也不读取科学输出；非零退出本身不能证明没有产生部分结果。

独立参考执行完成后，如果审查仅否决方法覆盖不足，可以进行一次受限增补。生成器统一返回追加协议，不重写整份计划；宿主复制原计划并追加检查，原数据、参数、退出语义、要求、断言及其标量类型和容差保持冻结。原参考源码和方法审查也冻结，增补后必须重新执行同一参考程序并取得绑定新计划摘要的完整记录，才能继续审查。原否决保留；数值、输入有效性、退出行为、支持范围被否决或无法确认时，不得借这条路径取得新的投票机会。

可观察结构不足采用同样的追加协议：`json_object_keys` 精确检查对象完整键集合，`csv_header` 精确检查完整有序表头；`stderr_contains` 检查普通拒绝的错误输出是否包含契约要求的角色名或短文本。错误输出原文不返回或保存，崩溃、超时和截断诊断不能作为该检查通过的依据。结构与诊断要求不能根据参考程序的输出自动改写。

增补可为已有用例追加结构、拒绝后置条件或诊断检查，也可新增正常、边界或无效输入用例。原字段、输入、值和容差全部冻结；新成功用例的有限数值预期仍须经过原参考源码的独立计算、限定纠正和确认执行，不能改写新用例的输入、目标或容差。每个原覆盖否决须得到实际新检查，或明确关联本次新增且共享原方法及来源的用例。关联本身不授予通过，仍须实际执行并重新审查。用例引用某项方法不等于单个用例必须穷尽该方法的全部分支，覆盖依据完整测试计划共同判断；不能逐轮升级原来源没有规定的穷尽验收义务。原有负评和历次确认依据完整保留。

同一方法、来源与接口下，严格追加的计划沿用原完整审查中正确性和容差均已通过的未变目标，记录原计划、审查和逐目标判定摘要；这些是沿用的证据，不伪装成新的模型回复。新增目标仍由独立模型审查，所有用例的输入、退出和覆盖判断重新检查，原覆盖否决不能随目标沿用而消失。旧目标曾被否决或无法确认时不允许沿用或重新投票。

详细验证记录及合成测试计划采用无损紧凑 JSON 打包，保留全部字段、原始判定、来源摘要和数值类型。减少缩进占用不会删除验证证据、缩短脚本或提高存储资源上限；技能介绍和小型方法资料仍可直接阅读。

技能包保存、下载和安装共用 64 个文件、1 MiB 未压缩内容的容量边界。超过容量时返回明确的 `package_too_large`，提示缩小技能范围，不提供对同一超限产物的直接重试入口；不删减方法、脚本或验证证据，也不将其他存储错误误归为容量错误。

## 中断恢复

创建是可恢复的构建流程，完成的阶段与待修复候选保存在私有 Redis 检查点，默认 24 小时过期。账户、会话、来源、模型配置和代码版本共同约束成果复用，任何恢复都重新执行结构、隐私和业务校验；检查点不是技能草稿，没有公开下载或安装入口。原来源和模型凭证只参与本地摘要计算，不以原文存入检查点。

重试从最近未完成阶段继续。科学方法被否决后继续修改最近候选；脚本执行失败后继续修复最近代码，并运行相同的冻结用例。模型或配置变化不能消除同一科学候选的已知否定结论，改写描述或重新排序也不能换取重新投票。无实质修改、整包校验失败的阶段成果会被清除，避免反复恢复相同失败候选。

缓存读写故障只影响恢复能力，流程仍可以重新构建；缓存操作有独立的两秒超时，不限制模型响应时间或输出长度。用户重试不重跑原分析，不修改已有结果，也不自动添加技能。

聊天创建链路没有整个任务的固定截止时间；SSE 心跳维持长连接，后台输入租约独立续期，页面断开不会自动取消创建。单个合成用例仍有执行保护。用户停止或服务重启可以中断创建，检查点不代表后台会自动重放；再次明确触发创建时才恢复。聊天工具记录会持久化创建阶段和状态，并在界面展示进度。草稿保存与聊天卡片写入不构成跨服务原子提交，因此不能把断线后的卡片状态等同于草稿存储状态。

参考执行无法确认时，该测试计划尚未冻结；仅清理本次访问的计划和参考程序正向阶段缓存，使用户下次重试能重新建立验证依据。已完成的分析方法和被测技能代码保留，负面科学审查记录也保留；环境不可用不会触发这一清理，不自动循环请求模型。

最新被否决的参考代码与完整审查单独保存，并绑定当时的盲审上下文摘要。用户重试时从这个版本继续实质修订，恢复前重新核对方法、接口、输入、覆盖和隐私。旧记录若只有否决代码而没有可信审查内容，继续保持否决，不编造原因或清除记录来重新投票。

## 验证范围

静态检查不代表方法正确；合成用例通过不代表整个泛化工作流或未来用户数据已验证。当前隔离验收支持声明式 CSV 行与字段、精确表头、JSON 标量、数组长度、对象键集合，以及拒绝输入后的输出为空断言。数组长度检查必须先确认实际值为数组，缺失字段、null、对象不能代替空数组；对象键检查拒绝重复 JSON 键，不读取单元格数值来推断结构；无需生成或执行测试表达式。当前合成 JSON/CSV 数值必须有限，不能声称覆盖了 NaN/Infinity 输入拒绝。不能验收的图像、复杂依赖或交互流程必须明确记录未验证范围，不得标成通过。

`CreationDependencies` 提供明确的模型、配置、计量、脚本执行和草稿存储注入点，避免靠修改旧模块全局变量来测试新的实现。

回归覆盖连续不同诊断、隐私误报与泄漏、科学覆盖、不可逆修改拒绝、冻结用例及草稿生命周期。人工验收场景位于 `backend/tests/skill_creator_scenarios.py`，包含多表关联、精确配对符号随机化及长宽表转换；预期值由独立人工小样例给出。真实模型验收入口为 `backend/tests/acceptance/run_skill_creator_real_model.py`，仅使用这些人工数据。
