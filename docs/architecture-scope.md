# DataLab 架构范围

## 产品边界

DataLab 面向科研人员的对话式数据探索与分析，支持开放数据检索和获取、文件上传、个人数据保存、分析和成果复用。它以 AI-DATASEEK 的 datalab 分支为起点，保留现有分析运行时。

- 研究问题入口：`/chat` 与 `/chat/:sessionId`。
- 个人数据空间：`/chat/my-data`；`/api/v1/data-library` 按账号保存不可变文件集合及来源、描述和标签。
- 本轮数据选择：`/api/v1/sessions/{session_id}/data-context`，验证文件和会话归属。选择结果只是当前输入，不替代会话历史。
- 分析技能库 `/skills`、数据连接器 `/connectors` 分设导航和管理页面。MCP、可视化插件、领域工具、领域预设和凭据分类隐藏；分析运行时仍使用这些底层能力。
- 上传文件统一使用已有分片上传流程，探索首页不显示 MCP 工具按钮。
- 机构数据的目录、登记、临时提交、专用探查页面及 HTTP 接口已移除。历史会话仍可解析已有只读挂载，真实服务器路径只保留在服务端，不进入响应、URL 或浏览器存储。
- 个人密码账号、最小注册审批，以及既有资源用量、任务、MCP、技能配置。

## 数据生命周期

开放数据或上传文件先进入现有对象存储；保存到“我的数据”时建立独立于会话的持久引用。来源凭据以服务器获取记录为准，检索清单仅代表元数据。分析结果可以保存并加入后续探索。

每份资产的文件集合固定为 v1，修改名称、标签不会修改原始文件。另一次保存产生独立资产，当前尚未实现完整版本谱系。保留引用与删除声明在 MongoDB 原子更新，避免保存与清理并发时丢失文件。移除数据条目只释放其引用，文件本身不会随之删除；旧对话删除和同名输出替换不清理仍被引用的对象。

会话选择最多 32 个已完成且属于调用者的文件。失效的选择会明确提示，避免静默改变分析输入。各次运行继续使用已有事件记录和来源凭据追溯，长任务自动恢复及完整数据谱系留待后续阶段。

## 身份与隔离

所有私有 API 需要有效登录凭证，文件下载和浏览器预览使用所有权校验或限定资源的短期签名。普通注册账号需管理员批准。匿名历史数据不会自动归属给新账号。开放数据通过连接器检索和获取；会话分享须由所有者主动发起。

## 部署隔离

DataLab 使用独立的 `docker-compose.yml`，Compose 项目和资源前缀为 `datalab`，应用镜像使用 `datalab-*`，默认前端端口为 `10030`。数据库与 bucket 的内部兼容标识保持不变；网络、卷和部署与原 DataSeek 分离。按用户的持续授权，修改通过必要检查后默认使用 `./run.sh` 更新受影响的 DataLab 服务，并验证健康状态及改动；用户明确要求不部署时除外。提交和推送仍需单独要求。

## 范围外

继续排除 Claw、A2A Agent 网络、科学站点发布、知识库索引以及泛平台管理。后台可恢复大文件下载、更多领域数据源和完整版本谱系属于后续阶段。本地源数据的只读挂载和主机路径白名单保持不变。
