# 分析技能的设计与验收

## 从具体分析提炼方法

- 区分本轮已经验证的方法和仅被建议的下一步。只固化前者；把未覆盖条件写入限制。
- 保留决定研究含义的字段语义、单位、聚合层级、缺失值策略和方法假设。将文件名、路径、范围、分组和阈值绑定到新任务参数。
- 固定阈值必须说明科学依据或让用户配置；不因原分析使用某个数字就把它写成默认事实。
- 依赖既可以是分析工具能力，也可以是脚本库。所有库和 API 均可使用，不设库名或 API 名单。说明实际可用性检查；缺依赖可在任务隔离环境准备，不扩大授权范围。若环境无法安装或兼容，说明具体缺口，不改变科学方法或重写基础库以绕过；无网络的验证环境不能假称安装成功。
- 若原分析已用可用库实现替代算法，保留其实际计算路径和检查，不能在技能里退回原先不可用的依赖。

## 完整性与可追溯性

先整理完整来源，再形成有稳定 ID 的方法要求清单。对每段原请求和成功方法证据说明所支持的要求；实际数值结论、一次性操作或重复文字可明确排除，不能借排除删除科学方法。原请求、完整方法与输出契约在创建过程中不得因字符或 token 限额截断。

在实际参数、步骤、脚本声明、输出和验证用例上就地标注 requirement_ids。由宿主程序生成覆盖索引，模型不填写数组位置；内容排序变化时索引自动随内容更新。算法名称、实验单位、对比对象和方向、校正家族、误差与区间算法、诊断规则、条件分支和验收都是方法的一部分，不可只保存“分析模型、生成图表”。独立审查其含义与原证据一致；未覆盖或改变时创建失败，不以宽泛摘要代替。

入口可以是索引，完整要求与覆盖关系保存在 method-contract.json，完整参数、方法和验收分别保存在引用文件；索引精简不等于底层方法精简。生成步骤数量由方法决定，脚本单独生成，不设置固定两步、固定两个参数或空脚本要求。

## 输入契约

每个参数都有可识别的名称、类型、必需性、默认值或空值、约束和作用。数据要求说明必需字段、单位、粒度、格式和缺失值处理。对于动态字段，使用字段映射参数。数据只能来自当前用户授权选择的数据或本轮查询所得数据。

区分输入的角色与一次性位置：例如“样本表”“测量表”“输出目录”是方法角色，当前附件名、下载地址和会话路径只是该角色本次的绑定。工作流、脚本和用例须共享同一份角色与字段映射约定，不能在说明里声称可配置、实现却只接受历史列名。替换位置不能删除方法含义：变量单位、统计方向、配对关系和有依据的阈值仍须明确保留。

## 步骤和分支

每个步骤写清操作、条件分支和可检查结果。例如，时序聚合应先检查时间字段解析、时区与采样间隔，发现重复时间或不规则采样时按方法适用性决定处理或停止。具体规则应来自源分析的方法证据，而非在创建技能时臆造。

## 输出契约与验证用例

结果要明确格式、必要字段/图表、质量摘要和验收标准。用合成输入设计至少一个正常、一个边界和一个无效输入用例；说明可观测预期，例如行数、排序、误差容限、空结果、拒绝原因。严禁用真实数据结果充当样例。

空 JSON 数组和记录数量使用声明式 `json_array_length` 断言，指定相对产物路径、JSON pointer 及精确 `length`；长度为 0 时必须实际返回数组，缺失字段、null、对象均不通过。`json_value` 只用于标量，不能把数组塞进其 expected.value 或用其它字段间接代替数组长度检查。

CSV 表格可使用 `csv_rows` 检查筛选后的精确行数；仅检查数量时 `fields` 为 `{}`，还需检查列值时填写逐列预期。零行不能同时声明列值预期。数量断言只证明记录数，不代替方法要求的统计数值、字段含义或其它输出验收。

验证分三层：包结构与参数完整性、辅助脚本语法/静态约束、在新数据或合成数据上实际运行。创建工具对支持的 CSV/JSON 脚本独立设计并冻结合成用例，隔离运行后核对真实输出；不得由脚本自行声明通过。报告必须以宿主实际记录为准，区分未运行、不支持和运行通过。合成用例仅验证其覆盖范围，当前数据的适用性和实际科学结果仍须在使用时检查。

验收不能只覆盖某一组默认字段和正常数据。按原方法选择具有区分力的案例：关联流程需检查重复键、未知引用与空分组；统计流程需检查实验单位、差值方向、有效样本分母、完整配对剔除与最小样本；转换流程需检查字段映射、单位缩放、空值与零值区别、重复单元格及排序。预期值从方法和全新人工输入独立推导，不能读取程序答案后修改断言。

冻结前须独立审查验收计划本身：逐项从原方法与合成输入核对预期数值、输入类别、异常语义和容差。精确枚举需核对所有组合、极端计数、阈值及分母。验证计划也可能算错，不能把未经审查的预期强加给脚本。只有审查确认后才冻结；不确定就明确报告，不能反复请求改判。尚未经过参考计算确认的候选计划，发现明确错误时可做一次实际修订，后续重试从最近被否决版本继续；不得换输入、删掉用例或放宽容差。参考计算确认后，文字审查不得再改写预期；最终冻结并执行被测程序后更不得据被测答案修改预期。

数值预期不能仅靠文字心算确认。创建流程在最终冻结前独立编写、审查并隔离执行参考计算：参考作者只看到方法、合成输入、公开接口和观察位置，不能看到候选预期、被测实现或被测输出。宿主可据完整、无歧义的实际参考计算纠正尚未冻结的标量预期；输入、目标、容差和覆盖保持不变，保留逐项纠正记录。参考实现不能在看到差异后改写以迎合候选答案；已经计算确认的预期也不能再被文字审查改写。无法确认的结构或数值必须停止，不能据此修坏原程序。

创建过程由宿主保存账户隔离、限时有效的中间成果。恢复时重新执行当前结构、隐私和业务校验；重试继续整理技能，不重跑原分析。只有模型配置、分析依据和代码版本相容的成果可复用；已知否定结论不能靠重复审查变成通过。脚本修复需从最近失败版本出发，对同一冻结计划重新实际运行，通过后仍须审查原方法是否完整。中间成果不是已发布或已安装的技能。

先确认脚本的公开调用接口，再设计验收。文件型输出必须传目标文件，目录型输出必须传目录；输出字段、文件名、格式和缺失语义也须一致。实现出错时修实现，接口说明缺失时补接口，不得为通过验收删掉科学方法或放宽已冻结数值容差。

验证范围必须对应真实检查对象。仅检查绘图程序附带的 CSV/JSON，不能声称 PNG、SVG 布局、字体或视觉质量已通过；仅部分脚本可执行时，要保留未覆盖脚本和原因。现有隔离运行器无法表达的图像、文档或专用科学格式，应明确报告验证范围和后续验收要求，不能自报完整运行通过。
